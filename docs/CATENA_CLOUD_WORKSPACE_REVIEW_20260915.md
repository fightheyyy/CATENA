# Catena 云端工作空间改造

本轮把主要体验收敛为「总览 → 经历 → 记忆 → 产出」，采用暖白底色、低饱和强调色、统一线条图标与阅读卡片。代码位于 `catena-web`，构建同步到 Go 的内嵌 Web 目录。本轮没有部署。

## 已实现

- **总览**：使用现有 Agent、Trace、分析 Job 接口，直接展示最近经历和简洁的产出列表。支持文本搜索、Agent 筛选、清除筛选、准确打开一条 Trace、进入产出的来源分析。某个接口失败时保留其他区域，失败区域显示错误与重试。
- **经历**：Trace 与对话整合为页内切换，旧地址继续有效。延续按 Turn 阅读、查看调用证据、展开原始 Span 的流程；手机压缩重复统计，给请求与回答更多空间。
- **记忆**：默认卡片，打开全文及来源后自动带到阅读位置。搜索保留事实、对话、主题三类结果，可一键返回全部；关系图按需加载，切换搜索时清理旧图。读取失败可以重试，失败不会被描述为没有记忆。有提炼任务或读取错误时才显示任务区域。
- **产出与连接**：简化页面标题和说明，降低内部协议术语的占比。产出保留阅读、文件复制/下载、来源、质量检查和删除边界。连接页保留专属凭证、两种 Shell 配置和首条数据检测。
- **全局外观**：四个主入口在手机底部固定；Agent、连接、设置与账户仍可访问。适配中文、英文、浅色、深色和系统主题，保留键盘焦点提示及跳过导航入口。

## 验证

针对“文字太多、不够精简”的反馈，继续移除了全局重复标题、标语、三张统计卡、记忆推荐面板与通用操作说明。记忆卡片以正文和日期为主，Trace 保留请求、调用证据与回答，产出阅读避免重复标题。错误恢复、来源、凭证和删除边界继续保留。

- 54 项单元测试、16 项浏览器旅程、TypeScript 与生产构建通过。
- 16 个构建文件与 Go 内嵌 Web 目录逐文件 SHA-256 一致。
- 浏览器场景覆盖总览空状态、局部接口失败和恢复、搜索到精确 Trace、产出来源跳转、异步产出更新、记忆全文/搜索/关系图、错误恢复及连接凭证处理。
- 实际检查了桌面 1440px、手机 390px 的页面截图；额外验证英文深色 320px 无横向溢出。
- 浏览器测试使用合成接口数据。它验证界面与交互，不代表真实 Agent 接入、模型产出效果、后端性能或账号间隔离已经重新验收。Go 业务代码没有修改，当前环境没有 Go 工具链。

## 预览与复现

在 `catena-web` 执行 `pnpm build`，再执行 `node tests/browser/preview.mjs`。终端会打印本机地址。预览使用 `tests/browser/workspace-sample.mjs` 的明确示例数据，不包含用户真实历史，也不会请求线上服务。退出终端即可关闭。

浏览器验收：`pnpm test:browser`。首次运行需安装 Playwright Chromium，或用 `CATENA_BROWSER_EXECUTABLE` 指向已有 Chrome。设置 `CATENA_BROWSER_ARTIFACTS` 可保存截图。首轮视觉材料保存在忽略目录 `.local/cloud-workspace-review/`，精简后的最终截图位于 `.local/minimal-refinement/`。

## 后续能力边界

当前记忆提炼来源仍是 XiaoBaOS 用户可见对话；通用 OTLP 提供多少内容，取决于导出端。跨 Agent 的长期个人/团队剖析、自动经验归纳及产出采用后的效果反馈尚未实现。这次完成的是精简且可用的工作空间与阅读流程。
