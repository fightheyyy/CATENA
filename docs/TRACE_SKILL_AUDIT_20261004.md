# Trace 对 Skill 候选的证据核对

核对日期：2026-10-04。目的：检查提出的 10 个 Skill 类别是否有历史 Trace 支撑。此次不构造新 Task，也不运行 A/B 实验。

## 数据与方法

- 全量复算本地导出中的 3,021 条 Trace、50,231 条工具调用和 Agent Turn 事件。
- 输入、输出和状态说明分别匹配；下表中的错误类次数取工具输出，heredoc 和 `.env` 读取次数取工具输入。
- 同一事件命中一个规则时只计一次；Trace 数按工作簿 Trace Key 去重。不同规则可能重叠。
- 工作簿文本每字段最多 600 字符，原始导出实际使用 ClickHouse `substring` 字节截取。匹配次数不能代表全量原文发生次数。
- 从命中记录中选取 20 条 Trace，回查 ClickHouse 原始事件前后顺序，共 668 条工具/Turn 事件。读取输入与输出前 12,000 字节、输出尾部 600 字节及总长度。抽样偏向早期事件，非随机抽样；不能据此估计误报率或恢复率。
- 原始文本、原始 ID 和本机路径仅保存在 `.local/failure-study/`。本报告只使用导出文件中的匿名 Trace Key 与 Event #。

## 可复算匹配次数

| 候选信号 | 事件数 | Trace 数 | 解释 |
|---|---:|---:|---|
| `ParserError` | 157 | 110 | 与网页 AI 给出的次数一致；输出匹配，非任务失败数 |
| 路径错误宽口径 | 164 | 114 | 包含 `FileNotFoundError`、`cannot find path`、`no such file or directory` 等；规则更宽 |
| 路径错误窄口径 | 124 | 85 | 仅 `cannot find path` 或 `no such file or directory`；未复现网页 AI 的 129/89，原规则未提供 |
| `ModuleNotFoundError` / `No module named` | 108 | 79 | 与网页 AI 一致；包括正常的环境探测输出 |
| `command timed out` | 102 | 61 | 严格字面匹配；未复现网页 AI 的 104/63 |
| `not a git repository` | 39 | 29 | 与网页 AI 一致 |
| `Failed to delete file` | 32 | 23 | 与网页 AI 一致；32 个事件均可观察到退出码 1 |
| heredoc 形式输入 | 44 | 31 | 与网页 AI 的 44 次一致；含合法 Bash 调用和源码补丁 |
| 读取 `.env` 形式输入 | 97 | 55 | 与网页 AI 的 97 次一致；含示例文件和合法配置检查 |

宽口径 `timeout` 输出有 875 个事件，其中 631 个来自 `wait_agent`；不能用这个口径计算命令失败。参数中的 `timeout_ms` 更不能算超时。

44 个 heredoc 输入中，26 个事件输出同时匹配 `ParserError`，涉及 23 条 Trace。该交集是候选失败集合，不是 44 次全部失败，也未逐条确认全部属于同一种 shell。

## 原始 Trace 的代表性核对

| Trace / Event | 原始步骤观察 | 对候选的意义 |
|---|---|---|
| T00020 / 7 → 8 | PowerShell 执行 Bash heredoc，退出 1；改为 Python `-c` 后退出 0 | 支持 shell 语法适配；已恢复，不能标作整项任务失败 |
| T00146 / 22 → 23 → 24 | heredoc 解析失败；第一次改写仍失败；第二次改写成功 | 支持多层引号和脚本传递问题；可测错误调用数和恢复成本 |
| T00020 / 16 → 17 → 18 | 猜测的源码路径触发 `FileNotFoundError`；列目录后读取实际文件成功 | 支持先发现路径再访问 |
| T00094 / 61 → 62 → 63 | 读取不存在的文件；枚举目录后读取存在的源码文件成功 | 同类路径问题出现在另一会话 |
| T00572 / 2 → 3 → 4 | PDF Python 依赖缺失；检查本地工具后使用 `pdftotext` 成功 | 支持依赖检查与替代工具选择，不必一律安装依赖 |
| T01206 / 15 | 枚举多个 Python 环境，捕获并打印 Torch 缺依赖；探测进程退出 0 | 正常诊断，不应计入待消除的错误调用 |
| T00310 / 19；T00057 / 16 | `git status` 在没有 Git 仓库的目录退出 1 | 支持 Git 上下文检查；尚不能区分错误 cwd 与项目本来没有 Git |
| T00343 / 14 → 15 → 16 | 绝对路径删除失败；换相对路径仍失败；接着读取文件 | 支持 patch 失败诊断；两次参数不同，不能直接判为盲目重复 |
| T00397 / 6 → 7 → 8 → 9 | patch 删除失败；改用 shell 写入；随后测试退出 1 | 支持修改后的独立验证；仅凭这些步骤不能证明重写损坏或删除根因 |
| T00049 / 17 → 18 | pip 安装超时；随后 `pip show` 返回 0 | 超时后应检查状态；不能据此断言包安装未完成或刚刚完成 |
| T00252 / 2 → 4 → 5 | 全套测试两次超时，第二次延长时限；随后一个定向测试通过 | 支持超时原因诊断与缩小验证范围；定向测试不等于全套通过 |
| T00231 / 33 | heredoc 文本出现在 Bash 脚本补丁中，patch 成功 | 明确的 heredoc 非失败匹配 |
| T00002 / 4；T00009 / 14 | 直接读取真实 `.env`，工具输出含未遮盖的 API Key 样式字符串 | 支持输出秘密控制；未验证凭据有效性，也未确认外部泄漏或用户授权边界 |

## 对原来 10 个类别的判断

| 类别 | 历史证据判断 | 能支持的范围 |
|---|---|---|
| S1 Windows Shell Expert | 证据较明确 | heredoc 与引号/脚本传递；pipeline、exe invocation 等需另外确认样本 |
| S2 Repo & Path Discovery | 证据较明确 | 访问前发现路径；nested repo 等仍需单独来源 |
| S3 Safe File Editing | 有失败事件，类别过宽 | 先改为 patch 失败诊断与可靠修改；没有证据证明 Delete + Add 本身导致数据损坏 |
| S4 Failure Recovery | 存在恢复过程，独立类别尚未确认 | 需要比较重复调用的参数、环境变化和恢复目的；不能用所有错误次数作来源 |
| S5 Secret-Safe Git Audit | 有实际风险样本 | 在完成配置/秘密审计时减少原值进入工具输出；不能把 97 次全部计为安全违规 |
| S6 Python Environment Resolver | 有实际失败，混有正常探测 | 排除诊断命中，聚焦解释器/依赖/替代工具；GPU 四任务方案尚未由这组数字支持 |
| S7 Git Context & Worktree | Git 上下文部分有证据 | 判断是否存在仓库和正确 cwd；dirty workspace、PR 测试污染尚无确认来源 |
| S8 Verification Before Done | 当前统计未证明 | 需要结合任务要求、最终答复、实际检查和独立结果；不能从零测试调用直接推出遗漏 |
| S9 Long-running Command Handling | 有真实超时，原因多样 | 分开处理安装、测试挂起、遍历范围和进程生命周期；固定工具运行语义 |
| S10 Completion & Delivery Evidence | 当前统计未证明 | 需要最终承诺、调用回执与产物状态的逐项核对 |

结论：网页 AI 找出了真实线索，不能把它们直接推广为 10 个均已确认的 Skill。S1/S2/S6/S7 的部分能力有直接支撑；S3/S5/S9 应收窄后使用；S4/S8/S10 需要追加证据。现有材料没有证明原方案的 40 个具体任务均来自独立历史失败，也没有证明 Skill 的效果。
