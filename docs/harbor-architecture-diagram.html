Harbor 框架全景

harbor-framework/harbor · Apache-2.0 · Laude Institute · Terminal-Bench 2.x 官方 harness  |  一次评测的完整数据流:任务 → 编排 → 环境 → Agent → 验证 → 分析

L1输入层 · 任务从哪来

Dataset Registry / Hub

registry.json 分发式数据集注册,harbor datasets list 即装即用;adapters/ 内 70+ 基准适配器:terminal-bench@2.x、swebench 全家、tau3、gaia2、osworld、theagentcompany、hle、livecodebench…

本地任务目录(Task)

一个任务 = 一个目录:environment/(Dockerfile)+ task.toml(指令)+ oracle(参考解,验证环境可解)+ verifier(评分逻辑)。可版本化、可离线复现。

Skills 自举

agent skills:create-task / create-adapter / publish / upload-parity-experiments —— 让 Claude Code / Codex 帮你写任务、写适配器、跑对齐实验。

▼

L2编排层 · Job / Trial

CLI 入口

harbor run --dataset terminal-bench@2.0 --agent claude-code -m <model> --env docker --n-concurrent 100

执行模型

job_plan.py 解析数据集 × agent × 环境 → Job 拆成并发 Trial(每 task×agent 一个独立试验,trial.log 全程留痕)→ storage/db 存结果。

▼

L3环境层 · 25 种沙箱 provider(--env 可插拔)

本地

docker(默认)· podman · dind_compose · apple_container · singularity · ssh

云沙箱

daytona · modal · e2b · ec2 · gke · openshift · runloop · blaxel · vercel · novita · beam · langsmith · hyperbrowser · skypilot · cua_cloud · hf_sandbox · kata(microVM)…

治理

capabilities(网络/权限能力声明)+ resource_policies(资源配额)——同一任务在不同 provider 上行为一致。

▼

L4Agent 层 · 谁来干活

installed 40+ 真实编码 agent

claude_code · codex · cursor_cli · gemini_cli · copilot_cli · goose · kimi_code · qwen_code · opencode · openhands · mini_swe_agent · swe_agent · devin · junie · trae_agent · vibe · cline · strands …

协议与桥接

ACP(acp_registry,兼容协议免写 adapter)· bridges(外部脚手架原样评测)· 自研参考 agent terminus_2(tmux 最小循环)· llms/models 多模型接入。

▼

L5验证层 · 分数从哪来

Task Verifier + Oracle

容器内跑 verifier 评分,oracle 参考解保证任务本身可解;agent 非 root、评测器可隐藏。

Rewardkit(独立可用)

声明式 criteria DSL:criteria.file_exists() / file_contains() … → reward.toml 按文件加权 → 输出 /logs/verifier/reward.json(即 RL reward 格式,uvx 可脱离 Harbor 单跑)。

Metrics 聚合

mean / max / min / sum + 自定义 uv_script,多 trial 结果汇总成 job 分数。

▼

L6产物与分析层

Viewer

本地 Web 查看器:逐 trial 回看轨迹、命令、评分。

Analyzer(LLM 归因)

rubric(analyze-rubric.toml)驱动 LLM 逐 trial 产出 analysis.json:失败原因、行为定性。

job_diff(对比)

跨 Job 对比、结果复用(REUSE)、重判定(regrade)——版本间"哪些任务过了/挂了"。

出口

榜单/报告 · RL rollouts(任务环境即训练环境)· atif2otel:ATIF 轨迹转 OTel span,可直连 Laminar 等观测后端。

hosted 云服务publisher / upload 发布telemetry 自身遥测packages: rewardkit · atif2otel · langsmith
Barena 收编点(1→100 分工)

直接采用:任务格式 + 40+ agent adapter + rewardkit(verifier 载体)+ job_diff(Compare 原型)+ environments 抽象(Docker 默认,Seatbelt/Bubblewrap 保留为进程级收紧层)。自研层:release truth 门禁(cleared/held/rejected)与 Run Bundle 契约 —— Harbor 只出分数,不做发布决策。
