# Catena 本地优化记录 · 2026-09-15

目前最影响产品体验的是流程衔接和结果反馈：用户能找到各个功能页面，但不总能顺利完成接入、定位证据、获得改进建议并验证效果。本轮先修复其中可以明确复现的断点，公开部署继续推迟。

## 本轮已落地

- 登录后的默认入口改为 Agent，新用户可以直接开始接入。
- 工作区按当前页面加载数据。原来全局等待九个接口；现在 Agent、API 管理各读取一个工作区接口，Trace 和 Trace Farm 各两个，设置无需工作区接口。登录和具体明细请求另计。
- 接口失败时保留导航和可用内容，提供重试；切换页面取消旧请求。
- 点击最近 Trace 会打开指定记录，链接可保存，刷新和后退不会变成另一条 Trace。记录不在当前时间窗口中时仍可直接读取详情。
- 进化任务完成后更新共享记录，资产库和分析历史同步变化；查看资产库时也会检测正在运行的任务。
- 接入页面提供 POSIX/PowerShell 配置、首条数据检测、失败重试和 Agent 跳转。真实密钥仅在复制时填入剪贴板，预览使用占位符。
- 补充窄屏失败返回入口，修复英文导航文字挤在一起的问题。

## 下一阶段最值得投入的工作

1. **让产物走到效果验证。** 候选应说明适用环境、修改内容、来源证据和采用方法；由本地 Barena 执行比较，把真实验证结果回传。模型审查通过不能被展示成已经改善了目标 Agent。
2. **让问题更容易定位。** 给 Agent 提供明确的时间范围、错误入口和可追溯的问题摘要；大列表需要分页与真实查询耗时测量，避免把最近一批记录误当成全部历史。
3. **让记忆更容易判断和维护。** 清楚呈现来源、提炼状态和召回理由，再设计纠错、删除等操作的权限和一致性规则。
4. **统一完整状态下的交互。** 用真实数据检查首次使用、空数据、处理中、失败、完成、权限失效以及键盘操作，而不仅检查有内容时的页面截图。

## 验收与边界

本轮通过 54 项单元测试、9 项浏览器回归、TypeScript 检查、生产构建，以及 14 个前端文件与 Go 内嵌目录的逐文件哈希比对。浏览器检查覆盖桌面与 390px，包含中英文及深色界面。

浏览器测试使用明确的模拟接口，不代表真实数据接入、模型运行、候选效果或服务端性能已经重新验收。Go 业务代码未修改；当前 Windows 环境没有 Go 工具链，Go 检查由既有 CI 执行。本轮没有部署到服务器。
